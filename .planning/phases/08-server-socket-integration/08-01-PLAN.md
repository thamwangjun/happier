<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| socket event → resilienceHandler | Untrusted socket event payload crosses into server handler |
| server → buffer DB | Server writes/reads UnackedMessage rows; no user-controlled key accepted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-8-01 | Elevation of Privilege | readBuffer / ackBuffer in resilienceHandler | mitigate | connectionKey is `user-scoped:${userId}` where `userId` is derived from the verified JWT in socket middleware — never from client payload; readBuffer is scoped to the authenticated userId |
| T-8-02 | Tampering | ReconnectResumeRequest.lastAckedSeq | mitigate | `ReconnectResumeRequestSchema.safeParse(data)` enforces `z.number().int().min(0)` before any DB access; malformed input is dropped silently |
| T-8-03 | Tampering | AckUpdateRequest.seq | mitigate | `AckUpdateRequestSchema.safeParse(data)` enforces `z.number().int().min(0)`; negative or non-integer seq values are rejected |
| T-8-04 | Denial of Service | reconnect-resume sent repeatedly | accept | Buffer is capped at 500 messages per user (RELAY_BUFFER_CAP); no rate limiting in v1.3 scope — acceptable risk given the cap |
| T-8-05 | Information Disclosure | replay of another user's messages | mitigate | readBuffer query uses `userId` from JWT — no cross-user read is possible; connectionKey is derived server-side |
</threat_model>
