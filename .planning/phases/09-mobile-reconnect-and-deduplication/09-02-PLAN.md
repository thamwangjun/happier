<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Inbound socket UPDATE event → dedup filter | All inbound seq values cross here before being applied to Zustand store |
| App background transition → MMKV write | saveLastAckedSeq must complete synchronously before iOS kills the socket |
| Multiple reconnect cycles → resumeViaChanges | Both MOB-08 and MOB-09 can fire per cycle; dedup guard prevents concurrent HTTP calls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09B-01 | Tampering | dedupFilter.ts | mitigate | `shouldApplyUpdate` uses `seq > lastAckedSeq` — any replayed event with seq already applied returns false; test: `shouldApplyUpdate(4, 4)` returns false, `shouldApplyUpdate(3, 4)` returns false |
| T-09B-02 | Repudiation | persistence.ts — saveLastAckedSeq | mitigate | MMKV write is synchronous (react-native-mmkv uses synchronous C++ API); `saveLastAckedSeq` completes before the AppState background handler returns; verified by MOB-05 test assertions |
| T-09B-03 | Denial of Service | ackCursorManager.ts — scheduleAckUpdateFlush | accept | Timer fires once per ACK_DEBOUNCE_MS=500ms maximum regardless of call frequency (dirty flag + early return); acceptable performance for message rates up to 1000/sec |
| T-09B-04 | Tampering | persistence.ts — loadLastAckedSeq | mitigate | Parse validation rejects non-numeric, negative, Infinity, or NaN seq values — returns 0 as safe default; attacker who corrupts MMKV gets 0 (full replay) not an elevated seq that would drop legitimate messages |
</threat_model>
