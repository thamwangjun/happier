<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| socket reconnect event → reconnect-resume emit | lastAckedSeq loaded from MMKV at this boundary; stale or zero value causes full replay (safe default) |
| REPLAY_START payload → gap check | retentionStart is server-provided; validated as typeof number before comparison |
| AppState background → ack flush | synchronous MMKV write at this boundary; iOS may kill the socket immediately after |
| replayGate → pendingQueueV2 HTTP POST | gate holds commits until replay-complete; wrong gate placement (optimistic store) would freeze UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09C-01 | Tampering | sync.ts — REPLAY_START gap check | mitigate | Validate `typeof payload?.retentionStart === 'number'` before comparison with `lastAckedSeq + 1`; a null/undefined retentionStart (empty buffer) does NOT trigger resumeViaChanges |
| T-09C-02 | Elevation of Privilege | sync.ts — AppState foreground handler (MOB-06) | mitigate | `apiSocket.disconnect()` called before `apiSocket.connect()` unconditionally; never trust `socket.connected` — verified by MOB-06 test case that passes `socket.connected=true` and asserts disconnect was called |
| T-09C-03 | Repudiation | sync.ts — background ack flush (MOB-05) | mitigate | `flushAckUpdateNow` + `saveLastAckedSeq` both called in the same try/catch block in the background handler; MMKV.set is synchronous C++ API — write completes before iOS WebSocket kill; MOB-05 test asserts both are called |
