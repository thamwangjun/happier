### Partial (2/18)

**1. SRVR-01 integration test permanently broken (affects: SRVR-01 test coverage)**

`vi.mock("@/app/events/connectionEventRouter", ...)` is hoisted to the top of `resilienceHandler.integration.spec.ts`, replacing `emitUpdate` with a bare `vi.fn()`. The test "SRVR-01: calls writeToBuffer" therefore always passes a mock function — the real `emitUpdate` (which contains the fire-and-forget `writeToBuffer`) is never executed. The production code IS correctly wired at `connectionEventRouter.ts:80`. Only the test assertion is broken; the implementation is correct. A test refactor is needed to isolate `writeToBuffer` directly rather than via `emitUpdate`.

**2. VALID-01 E2E test doesn't exercise CLI-sender path (affects: VALID-01, STORE-07)**

`reconnect.resilience.e2e.test.ts` creates DeviceA (sender) with `createUserScopedSocketCollector`, so DeviceA has `clientType: 'user-scoped'`. A real CLI sender would have a machine-scoped or CLI connectionKey, triggering the STORE-07 guard in `writeToBuffer` (which would skip buffering for CLI connections). The E2E test validates the core reconnect-resume loop correctly but the CLI→server→mobile path and the STORE-07 exclusion path are not exercised end-to-end. STORE-07 is covered by unit tests in `unackedBuffer.spec.ts`.

---

**3. PROTO-04 ackSeq runtime use case (affects: PROTO-04)**

The `ackSeq: z.number().int().min(0).optional()` field was added to `UpdateContainerSchema` in Phase 6 (`packages/protocol/src/updates.ts:243`). No server-side code path sets `ackSeq` on outbound update payloads. No mobile-side code reads `container.ackSeq`. The piggybacking design (server hints ack position on outbound updates to save a round trip) was implemented at the schema level but not at the runtime level. Backward compatibility is preserved — existing clients are unaffected — but the efficiency optimization described in the Phase 6 plans is inert.

**Impact:** Low. The requirement (PROTO-04) specifies the schema field exists, which it does. The unimplemented optimization is a backlog item.

### Other Integration Notes

- **`STORE-05` overflow return unused:** `writeToBuffer` returns `{ overflow: boolean }` but `connectionEventRouter.emitUpdate` discards the return (fire-and-forget). Overflow is instead detected at reconnect time via a `db.unackedMessage.findFirst` `absoluteMin` query in `resilienceHandler.ts`. Functionally equivalent — STORE-05 requirement is met — but the `writeToBuffer` overflow return is dead output.
- **`VALID-03` naming mismatch:** Requirement says "SQLite WAL contention" but `buffer.walContention.stress.test.ts` comment (line 23) clarifies the target is PostgreSQL connection pool saturation. Test is real and passes (BURST=200 concurrent writes via `Promise.all`); the REQ-ID description is inaccurate.
- **`replay-complete` payload shape:** Server emits `{ retentionStart }` on all three paths (`resilienceHandler.ts:30,55,90`). Protocol docs say no payload. Mobile listener at `sync.ts:3360` uses zero-argument callback and discards the payload silently. E2E test also ignores it. No functional break — Socket.IO delivers extra fields to listeners that don't declare them — but `docs/protocol.md` needs updating.
- **`RELAY_BUFFER_CAP_DEFAULT` / `RELAY_BUFFER_TTL_MS_DEFAULT` constants:** Exported from `backends.ts` but never imported directly by consumers. Both values reach the runtime transitively through the resolver functions. Functional contract of PROTO-05 is met.
