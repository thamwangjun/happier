### Integration Issues

**⚠️ WARNING — PROTO-01/PROTO-05: Documentation gap**

`replay-start` event is emitted by `resilienceHandler.ts` and consumed by `sync.ts` but absent from both `docs/PROTOCOL_CHANGES.md` (which lists only the 4 original events) and `docs/protocol.md` v1.3 section. Similarly, `RELAY_BUFFER_CAP` and `RELAY_BUFFER_TTL_MS` env vars are implemented (`apps/server/sources/config/backends.ts:52-61`) and connected to the runtime but not documented for operators.

An operator deploying this server cannot discover these env-var configuration knobs or the `replay-start` event contract from public docs.

**ℹ️ INFO — shouldHoldServerCommit orphaned export**

`apps/ui/sources/sync/engine/resilience/replayGate.ts` exports `shouldHoldServerCommit` which is spec-covered but never called in production code. MOB-07 gate behavior is implemented via direct `replayGate.isReplaying` field mutation and `waitForReplayComplete()`. No behavioral gap.

**ℹ️ INFO — ackSeq field inert on mobile**

`UpdateContainerSchema.ackSeq` is parsed by `socketParse.ts` but `container.ackSeq` is never read in `sync.ts`. The field is a future-use server hint; no consumer exists today. No protocol break — extra fields are silently ignored by Socket.IO listeners.
